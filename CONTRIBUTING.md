# Contributing to Solohub

Thank you for your interest in contributing to Solohub! Solohub is a free and open-source GitHub control center Chrome Extension for solo developers.

---

## Code of Conduct & Core Principles

1. **Free & Open Source**: Solohub is and will remain free and open source. We do not accept telemetry, analytics, monetization, ads, or paywalled features.
2. **Security & Privacy First**: Never commit credentials, tokens, secrets, or `.env` files. Respect user privacy and adhere to the security guidelines in [SECURITY.md](SECURITY.md).
3. **Respectful Collaboration**: Maintain a welcoming, inclusive, and professional environment for all contributors.

---

## Development Prerequisites

- **Node.js**: v20.0.0 or higher
- **Package Manager**: [pnpm](https://pnpm.io/) v9 or v10 (`npm i -g pnpm`)
- **Browser**: Google Chrome or Chromium-based browser supporting Manifest V3

---

## Repository Structure

- `src/`: Chrome Extension frontend application (React 19, TypeScript, Tailwind CSS, Vite).
- `public/`: Static assets and icons for the Chrome Extension.
- `manifest.config.ts`: Manifest V3 definition with mode-aware permissions.
- `server/`: Optional Node.js/Express OAuth token exchange backend.
- `scripts/`: Build and packaging utilities (`package-release.mjs`).
- `tests/`: Frontend and manifest unit tests.

## Getting Started

### 1. Clone Repository & Install Dependencies

```bash
# Clone the repository
git clone https://github.com/your-username/solohub.git
cd solohub

# Install frontend dependencies
pnpm install

# Install backend dependencies
cd server && pnpm install && cd ..
```

### 2. Configure Environment (Optional)

If developing the OAuth authentication flow, create local environment files:

```bash
# Frontend configuration
cp .env.example .env.local

# Backend configuration
cp server/.env.example server/.env
```

> **Warning**: Never put real GitHub client secrets or personal access tokens into `.env.example` or any tracked files.

### 3. Start Development Servers

Run the extension development server (with hot module replacement):
```bash
pnpm dev
```

To run the optional authentication backend concurrently:
```bash
cd server
pnpm dev
```

### 4. Load the Extension in Chrome

1. Open Chrome and navigate to `chrome://extensions/`.
2. Toggle on **Developer mode** in the upper-right corner.
3. Click **Load unpacked**.
4. Select the `dist/` directory generated by the build/dev server.

## Verification Commands

Before submitting a pull request, ensure all linters, tests, and builds pass cleanly:

### Frontend Verification

```bash
# Run ESLint (must pass with 0 errors and 0 warnings)
pnpm lint

# Run unit tests
pnpm test

# Run production build check
pnpm build

# Test reproducible release packaging
pnpm run package
```

### Backend Verification

```bash
cd server

# Run backend unit tests
pnpm test

# Run TypeScript compilation
pnpm build

cd ..
```

## Pull Request Guidelines

1. **Branch Naming**: Use descriptive branch names like `feat/issue-filters`, `fix/command-palette-focus`, `docs/readme-updates`.
2. **Commit Hygiene**: Write clear, concise commit messages. Do not bundle unrelated changes together.
3. **Never Commit Secrets**: Ensure `.env`, `.env.local`, `.env.production`, release ZIPs, or personal tokens are never staged or committed. Check `git status` before committing.
4. **Testing**: Add unit tests in `tests/` for any new logic, security validation, or manifest configuration changes.
5. **UI & Accessibility**: Preserve dark-mode styling consistency, responsive layouts, and keyboard navigation.

---

## Reporting Issues & Requesting Features

- **Bugs**: Open an issue describing what occurred, the expected behavior, your Chrome version, and reproduction steps. **Never include authentication tokens, client secrets, or private repository names in screenshots or logs.**
- **Security Vulnerabilities**: Follow the private reporting process outlined in [SECURITY.md](SECURITY.md).
- **Features**: Propose feature ideas via GitHub Discussions or issues before opening large pull requests.
